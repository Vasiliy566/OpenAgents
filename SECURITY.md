# Security policy

OpenAgents currently accepts only packages generated by AppInside for hosted applications with isolated customer access.

## Enforced checks

- Fixed allowlist: `plugin.json`, `mcp.json`, `README.md`, bounded PNG/JPEG images.
- Portable Agent Plugins manifest, required presentation fields and referenced assets.
- Exactly one HTTPS `streamable-http` MCP endpoint on the configured AppInside origin with the expected app ID and OAuth endpoint path.
- No stdio process, command, arguments, environment values, authentication headers, hooks, skills, scripts, HTML, uploaded executable archives, symlinks or path traversal.
- Known private-key/token/JWT patterns and credential-bearing public URLs are rejected.
- PNG structure, checksums, dimensions and trailing content; JPEG signature and existing AppInside image validation.
- Files are screened before a Git write; catalog state is confirmed only after the remote commit is confirmed.

These checks do not establish that every action of a remote service is safe. Secret detection is pattern based, not exhaustive. UI and business operations remain hosted; users should review requested permissions and authorize their own service accounts. Do not publish sensitive data in descriptions or screenshots.

## Report a problem

Use [AppInside support](https://appinagents.ru/studio/support) or email **support@appinagents.ru**. Do not include credentials in public issues. Provide the plugin name, version, relevant commit and a concise description.

We may remove an affected entry from the current marketplace and disable its hosted release. Already public Git history and copies cannot be recalled by catalog removal.
